# AI 编程助手规则文档快速初始化指南

> 本指南帮助团队在 **90 分钟内** 完成规则文档初始化

---

## 📋 前置准备

- [ ] 选择 1 个试点项目（建议选择核心业务项目）
- [ ] 准备项目基本信息（技术栈、架构文档）
- [ ] 组织 2-3 人参与（技术负责人 + 资深开发）

---

## ⏱️ 90 分钟初始化流程

### 第 1 阶段：项目扫描（20 分钟）

```bash
# 在项目根目录启动 Claude Code
cd /path/to/project
claude

# 输入以下分析指令
"请分析这个项目的：
1. 技术栈和依赖（package.json / requirements.txt / go.mod）
2. 目录结构和分层架构
3. 常用命令（构建、测试、运行）
4. 代码风格特点"

# 记录 AI 分析结果
```

### 第 2 阶段：痛点收集（30 分钟）

查看最近 3 个月的 Code Review 评论，找出：
- 重复出现的同类问题
- 团队经常纠正的错误
- 曾经引发线上故障的操作

**痛点收集模板**：

| 问题描述 | 频率 | 优先级 | 转化为规则 |
|----------|------|--------|------------|
| [描述] | 高/中/低 | P0/P1/P2 | [对应规则] |

### 第 3 阶段：架构红线确认（20 分钟）

与架构师确认：

- [ ] 哪些技术/库是明确禁用的？原因？
- [ ] 分层架构有哪些绝对不能违反的规则？
- [ ] 有哪些安全约束是必须强制执行的？
- [ ] 有哪些历史遗留问题是 AI 不知道的？

### 第 4 阶段：文档填充（20 分钟）

基于模板填充信息，遵循"删减原则"：

> 对每一条规则问自己："如果删掉这条规则，Claude 的输出会变差吗？"
> - ✅ 会变差 → 保留
> - ❌ 不会 → 删除
> - ❓ 不确定 → 测试验证

## 📁 文件放置

```
项目根目录/
├── AGENTS.md          ← 项目操作手册（提交 Git）
├── CLAUDE.md          ← AI 行为准则（提交 Git）
├── CLAUDE.local.md    ← 本地私有配置（加入 .gitignore）
└── docs/              ← 详细规范文档
    ├── architecture.md
    ├── testing-guide.md
    └── security.md
```

## ✅ 验证规则有效性

创建文档后，必须验证：

1. **新开 Claude Code 会话**
2. **给一个应该触发该规则的任务**
3. **观察 Claude 是否遵循**
4. **结果判断**：
   - 遵循 → 规则有效，保留
   - 不遵循 → 规则表述不清，重写

---

## 🔄 持续迭代机制

### 触发添加规则
- AI 重复犯错 2 次以上
- Code Review 中经常出现同类反馈

### 触发删除规则
- 文件超过 150 行
- 规则从未被触发
- 对应技术已废弃

### 月度 Review
- 每月 Review 一次规则文件
- 删除过时规则
- 补充新规则
