# Legacy Rule Miner 方法论

## 五大核心原则

1. **Copy-Paste First** — 新代码必须模仿最近的同类代码
2. **No Surprise** — 禁止引入项目从未使用过的模式
3. **Version Lock** — 禁止升级依赖版本，除非明确要求
4. **Gradual Improvement Only** — 只能做方法内的安全改进
5. **Pitfall Awareness** — 已知陷阱必须显式标注

## 应用方式

### 在 Wiki 生成中
- 从代码中提取已有的编码模式，标注为"项目已有模式"
- 识别项目中未使用的模式，标注为"禁止引入"

### 在规则文件生成中
- 将五大原则写入 CLAUDE.md 的"核心原则"部分
- 从代码中提取已知陷阱，写入"已知陷阱"部分
- 从 pom.xml/package.json 中锁定依赖版本，写入"版本锁定"部分

### 规则可测试性
每条规则必须满足：
- 给出规则 → 能验证 AI 是否遵循
- 包含真实代码示例（从项目中提取）
- 禁令搭配替代方案
- 未知内容标注 `LOW_CONFIDENCE`
